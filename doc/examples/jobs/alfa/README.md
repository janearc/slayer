# Moonlit Alfa underway clip

`game run cavitation-clip-plan -- --recipe doc/examples/jobs/alfa/plan.yaml`
authors120 actual1080x960 scene snapshots and native Slayer draw jobs. It does
not render pixels. The local HALF-PORTRAIT convention is9:8,1080x960.

A common linear map-space trajectory moves the Alfa and its attached screw
field forward at approximately3m/s. The camera tracks the same trajectory.
Each job supplies its actual timestamp i/12s to the renderer, so the analytic
300RPM rotor phase, advected density fragmentation and scene-clock ocean use
the same physical clock. This is real object/field motion despite the tracking
camera; no still-image warping or optical frame interpolation is used.

The template uses the stern/cavitation view, actual modeled Moon,
64water single-scattering steps, phase0, clear/cloud composition, explicit
ray-spacing quadrature and10stop development. Diffuse-sky quadrature is
explicitly omitted: direct Moon keeps the mood while reducing cost. This is an authored shot approximation,
not a solved propeller pressure field or resolved individual bubbles.

Draw each numbered job with the same pinned Slayer binary; jobs write PNG
frames and separate linear PFM masters. After all120 exist, native
`slayer draw jobs/encode.yaml` develops the PFM masters and encodes exactly
10seconds at12fps. Keep outputs outside git, preserve receipts and source pins,
and verify decoded dimensions/frame count/duration before delivery.

Plans use Puzzlemouth `yamlfile.Schema.Read`; templates pass canonical
`set.Read` before Puzzlemouth AST transformation. There is no second plan
parser.

When a template defines a residual population under `world.fizzes`, optional
`attached-fizzes: [residual]` names the populations whose feet share the boat
trajectory. Only explicitly selected feet move. Omission or an empty list
keeps every Fizz fixed, including unrelated environmental populations.
The plan rejects duplicate or missing names, nonnumeric feet and incompatible
world/position units before writing snapshots. This changes no existing clip.

An optional `camera-orbit` defines a continuous map-space camera path around
an authored centre. It requires `camera-tracking-fraction: 1`: both eye and
aim follow the subject translation. Azimuth zero is north and positive turns
toward east; elevation is positive up.

For normalized time `u = t/seconds`, azimuth is `azimuth-deg + 360*turns*u`;
elevation is `elevation-deg +
elevation-amplitude-deg*sin(2π*elevation-cycles*u + elevation-phase-deg)`.
The eye offset is radius times `[sin(azimuth)*cos(elevation),
cos(azimuth)*cos(elevation), sin(elevation)]`; the aim is the moving centre.

The last frame is at `(frame-count-1)/fps`, not at the duplicated endpoint.
Integer turns and elevation cycles close continuously at the true duration.

```yaml
fps: 24
seconds: 30
rays: 1
vertical-view-deg: 55
camera-orbit:
  centre: [-1500, 0, -55.25]
  radius-m: 85
  azimuth-deg: 160
  turns: 1
  elevation-deg: -10
  elevation-amplitude-deg: 25
  elevation-cycles: 1
  elevation-phase-deg: 0
  surface-up-m: 0
```

Optional `surface-up-m` refuses the entire conservative continuous eye/aim
envelope if it reaches that authored mean-surface height, including vertical
subject translation. It does not test waves, hull collision or clearance from
other geometry. The elevation envelope stays within ±89 degrees to avoid a
polar camera singularity. All coordinates and controls have finite numerical
bounds.

Independent quality choices `rays` and `vertical-view-deg` default to
1 and80 respectively; omission preserves prior generated bytes. Orbiting
does not change rotor RPM, shutter, optics, scattering or exposure.

Optional `start-seconds: 0.7` starts the native source clock at0.7seconds:
each emitted job uses `start-seconds + frame-index/fps`. Subject translation,
camera orbit and attached fields' positions still use elapsed time beginning
at zero. This selects the initial advected medium/rotor state without moving
the initial boat or camera. The finite offset is bounded0..86400seconds;
omission defaults to0 and preserves existing output bytes.
