# Slayer v0.1.2: brief for review, and its record, 2026-11-12

This branch is one day's work for the v0.1.2 release: a front door
(`slayer` and its verbs), a job document that says how to draw, films
written without ffmpeg, the synth brought into the tree, a live view and
an editor, blur and depth of field in the kernel, disk caches, an opt-in
fast light, and the explainer and walkthrough shorts with the tools that
make them. The changelog's v0.1.2 section says what each does.

The first half of this file is the brief for a reviewer: where the work
is, what to read first, what to try, and what is already known to be
wrong. The second half is the record of the review it already had.

## How to review it

### The diff

    git diff e8427ea9..fable-team/final-2026-11-12

913 files, about 110,000 lines added. Most of it is data and leaves:
the tune library (`cheeptune/library/`) is about a fifth of the files,
and the `improv/` packages are tools for making particular films. The
code most worth a reviewer's time is a small part of it.

### Read first, in this order

1. **The kernel**, `gpu/trace.metal` and its Go side (`gpu/exposure.go`,
   `gpu/reach.go`, `gpu/sky_share.go`, `gpu/frames_held.go`,
   `gpu/structure.go`). Four changes were written separately and merged
   by hand: blur and depth of field at the primary ray, a forward lobe
   for mist, fast light's lamp store and shared sky looks, and kept mesh
   trees.

   Each claims that with its switch off every picture is what the
   kernel drew before, byte for byte; `gpu/kernel_unchanged_test.go`
   pins six pictures to prove it, and a seventh (a closed thin lens) as
   it is drawn now. Ask: can a switch that is off still change a
   picture, and do two switches on together give a wrong one.
2. **The keys**, `job/inputs.go`, `job/canonical.go`, `door/keys.go`,
   `door/kept.go`, `diskcache/`. A key that misses an input silently
   reuses a stale picture or film; that is the worst fault this release
   can have. Ask: what changes a picture and is not in its key.
3. **The door**, `door/` and `cmd/slayer/main.go`: what `draw` writes,
   overwrites and removes (working frames, the dated folders under a
   renders home, `slayer cache --clear`), and what `edit` runs.
4. **The session**, `hillside/session*.go`: a scene staged once, its
   frames drawn one at a time.
5. **The movie bridge**, `interfaces/movie/bridge.m` and `bridge.go`:
   Objective-C behind cgo, used by every film.
6. **The voting server**, `cheeptune/audition/server.go` and
   `door/tunes.go`: an HTTP server on loopback, reached from a browser.

The rest (`cheeptune`'s engines, `improv/`, `scene/named`, the docs) is
lower risk: wrong output there is seen, not silent.

### Run

Every test needs `GOWORK=off`; the GPU tests need a Metal device and the
shelf (`SLAYER_SHELF`). Through Game: `game test -- ./gpu/` and
`game test -- -timeout 60m ./hillside/` are the long ones (four and
seven to twenty-five minutes, by the machine's load); the rest by
package.

One test fails before this work as after it:
`burning-trousers/mesh`'s `TestSlayersMeshDrawsWhatAShapeMeshDoes`, on
the MCRN Larson.

### Try by hand

- `slayer` with no verb, at a terminal: the editor's panes.
- `slayer draw jobs/short-fire-night.yaml`, stop it with control-c, run
  it again: it resumes. Change the job and run again: stale frames are
  redrawn.
- `slayer watch jobs/smoke-still.yaml`, then save the job: it redraws.
- `slayer list`, `slayer assess --smokes 7`, `slayer cache --dry-run
  --clear`.
- `slayer draw --fastlight on` on a set with mist, against the same
  without: the record says which.
- `slayer tunes DIR` on a folder of tunes: the voting page.

### Already known

Under "Left, with reasons", below. The two that matter most: no key
covers the files a set reads in turn, and two job files of one name
drawn on one day share a dated folder.

## The review it had

### Review boundary

- Base: `rc-v0.1.2` at `e8427ea9`, the release candidate the day began
  from. The release branch contains it whole; merging is a fast-forward.
- Reviewed: the merged candidate `603a2a6f` (`fable-team/fold-2026-11-12`).
- Fixed: `fable-team/review-fixes`, eleven commits on top of the
  candidate, each with a test and, where one could be written, its
  anti-test.
- Released: `fable-team/final-2026-11-12`, the candidate with the fixes
  and the documentation merged.

Each area was read by a session that wrote none of its code, at a stated
model and effort. A last pass, by another such session, tried to break
the fixes; what it found is under "The fixes, broken and mended".

### Areas

### Fixed

- **job.** A played scene's cue sheet is an input whose bytes are in
  the key, and its sound stays in its picture key: frames drawn to old
  music were taken for new. A job whose canonical form cannot be written
  as JSON is refused; it used to get the key of nothing, shared with
  every other such job.
- **door.** A kept still is served only where `SLAYER_KEPT_STILLS` is
  `on`: its key does not hold every file a set reads from beside itself
  (its hud theme, for one), so a still served by default could be an old
  picture of a changed set. The served picture is written through a
  temporary file of its own.
- **watch.** The terminal is given back when the view or a frame panics.
- **hillside.** A rig's film refuses fast light when it opens; it drew
  exact light and said nothing. A cancel stops between a shutter's
  glimpses.
- **movie.** The finish waits a minute a thousand frames, not one minute:
  a long film's final rewrite could time out and be thrown away. Seeking
  allows a nanosecond, so a moment at a frame's edge shows that frame.
- **slayer.** The build's digest is started as the binary starts, so a
  binary rebuilt during a run cannot put its digest on what the old one
  kept.
- **gpu.** The sky's looks are shared only where they are dealt evenly:
  one, two, four, eight or sixteen samples along a side. At three a pixel
  took nine of the sixteen in a row.
- **gpu.** A closed thin lens's picture is pinned as the kernel draws it
  now (see contract item 13).

### The fixes, broken and mended

The breaking pass rejected two of the fixes:

- A film guard that refused a film over another same-named job's movie
  compared the job files' bytes. It refused the same job drawn again
  after an edit on the same day, which the release line allowed. It was
  taken out. Two job files of one name drawn on one day still share a
  dated folder; a claim by the job file's path is owed.
- The first sky-sharing rule stopped sharing at eight and sixteen a
  side, where the kernel deals evenly, and broke an existing test. The
  rule and the test were mended, with three a side as the anti-test.

A pty test of `watch` failed once under load, reading the status file a
moment before it was written; it now waits for it.

### Left, with reasons

- **No key covers the files a set reads in turn** (terrain, shelf
  assets, its hud theme). A film resumes old frames after one of them
  changes. Mending it needs the set package to report what it read. Until
  then a kept still is not served by default.
- **A pinned file's re-hash is decided by its size, time, inode and
  device.** A file replaced in place with all four kept is taken as
  unchanged. Adding the change time is the next step.
- **door:** a film's key lacks the shelf's sources list; a job's outputs
  may name any path; a second control-c and `q` wait for the frame being
  traced; SIGTERM skips the stopped status; two watches share a status
  folder; two draws of one job share a working folder; quoting in
  printed commands and in the nvim key.
- **hillside:** some refusals come at the first frame rather than at
  open; Open's package-level stamp is unguarded; a job's focus is taken
  in metres; the hud is placed at the shutter's opening.
- **caches:** the trees store lives outside the cache home; the per-pid
  trees store can race a slow merge (both experimental, opt-in).
- **job:** lazy hashing of inputs; absolute paths in the key (false
  misses only); integers above 2^53 in a named scene's parameters.
- **movie:** reading a sound holds four copies of it; a dropped writer
  leaks; a damaged file's missing format description reaches CoreMedia.
- **voting server:** a tune name with a digit refuses the folder; a bad
  ledger answers 400; no read timeouts.
- **kernel:** a thin lens with an eye scale other than one may focus
  differently from the CPU tracer; a test at scale two would settle it.

### Tests on the released branch

Build and vet clean. The whole `gpu` suite and the whole `hillside`
suite pass. Every other package passes except
`burning-trousers/mesh`'s `TestSlayersMeshDrawsWhatAShapeMeshDoes`,
which fails on the MCRN Larson (2 to 12 pixels past one just-noticeable
difference) on `rc-v0.1.2` itself, before any of this work.

### Contract changes

1. job-v1: a camera path's unit is the scene's own.
2. job-v1: `print.stops` runs from -40 to 40 (was -20 to 20).
3. job-v1: `outputs.note` is words, not a path.
4. cheeptune score format: loudness marks and a `tempos` list. tune lives
   in Slayer now, so there is no other copy of the format to keep in step.
5. cheeptune voicing format: `machine: studio`.
6. cheeptune cut sheets, `NAME.cuts.json`, a new document.
7. A film's frames are working files, removed once the movie is written
   unless asked for; stale frames are redrawn, not refused; the resume
   key covers every input file's content and the build.
8. The old commands are removed as their verbs land.
9. The catalogue carries on past a failed specimen and resumes.
10. The Metal kernel's header grows for blur and depth of field.
11. Fast light is a choice of how and for whom a picture is drawn: for
    pictures going to a video site, never the default, said in the
    picture's record.
12. `vibes`, `fastlight` and `shortcuts` as flags of a job, a set and the
    door, beside `fantasy`; the strict setting, science, is separate and
    refuses every shortcut.
13. A thin lens's closed pictures are drawn from rays the kernel makes,
    within the exact tolerance of the CPU's, not byte for byte. Full
    proof stays available: the CPU tracer, which the proof path replays,
    is unchanged.

## Outstanding from the day's plan

The day began from a plan of about 450 lines ("Slayer: one front door,
interactive, shorts first"). Checked against this branch, item by item,
these were not built or were built only in part. Each says what exists
and what is owed.

### Not built

- **`slayer send`**, the azazel record of a job, through a seam with
  nothing to run it. No verb, no seam.
- **Cancellation inside a frame.** The plan asked for cancellation on the
  CPU's rows and the GPU's bands, with a sentinel test that fails on a
  leaked goroutine or device buffer after a cancel. A session checks its
  context before a frame and between a shutter's glimpses; the tracers
  take no context, so a frame being traced runs to its end, and `watch`'s
  `q` and `draw`'s control-c wait for it.
- **Preview quality as a way of drawing.** `quality: preview` is read,
  checked and kept in the key, and changes nothing drawn (the session
  records it). The plan's preview (fewer rays, fewer volume steps, cached
  lighting, smaller frames scaled up, said on screen) exists only as
  `watch`'s ladder of sizes and rays. Fast light covers part of the
  speed for mist.
- **A picker of shorts**: spans of a score and cue sheet that cut
  cleanly on downbeats, flashes and transitions, a job emitted for each,
  snapped to bars. Overtaken by the explainer
  and walkthrough formats, which choose their spans by hand: crops of the
  moonlake film "did not hold the viewer".
- **The catalogue as a batch of jobs**, coming through the front door.
  `cmd/catalogue` carries on past a failure and resumes, and writes the
  PDF from the same record as the HTML; it is not a job and not a verb.
- **The remaining commands on the door.** `slayer render` is read ahead
  of the door in its own flags. `show` (with a folder-watching mode and no
  default path), `grissom`, the shelf verbs (`sources`) and the named
  scenes' own commands (`swarm`, `ring`, `moonrise`, `orbital`) are still
  separate binaries. Seventeen commands became one front door with nine
  verbs and fourteen commands beside it.
- **Kitty pixels** in `watch` where the terminal takes them
  (`interfaces/kitty`). `watch` draws sextant cells only.
- **A set file for each named scene.** `scene/named` was agreed as a
  bridge: each named scene is owed a set, and `named` goes when the last
  has one. None has one yet, and the registry grew by three (zappy,
  magnetar, weather).
- **Omnipositor's hook** into the movie bridge (the omnipositor branch).
  Not looked at; no second compositor was written either.
- **A GUI** on `watch`'s status folder. The folder (`frame.png`,
  `screen.png`, `status.json`) is published for one; nothing reads it.

### Built in part

- **`slayer edit`.** The tmux layout is built from tested argument lists
  and has never been run in a real tmux. Hover needs
  `yaml-language-server` and the console needs `carrie`, neither on this
  machine's path; `edit` says so by name and runs without them. Not
  driven under a pty, as the plan's verification asked.
- **Music written by an agent from a request**, with the strict
  validator's errors driving the retry. The format is taught in
  `cheeptune/SCORING.md` and `cheeptune/VIDEO.md`. The plan's page teaching it through
  `--agent-help` was not written: `--agent-help` lists the verbs and
  their flags only. Whether a small, cheap model can write a valid tune
  from the docs was not tried.
- **A supplied audio file's beats.** A film may take a sound file with a
  score beside it for its beats; finding beats in the audio itself, stated
  as approximate, was not written.
- **Motion blur on things that move.** The kernel's shutter blurs the
  camera's move; moving things (zappy's beams) are still blurred by
  drawing glimpses, at the cost of a frame each. A set's rig in a film
  takes its lens through the kernel, but not the kernel's shutter.
- **The space stage.** Smoke 50 as a set, the lantern kind with cameras,
  and `culture-orbital` among a space set's kinds exist. The date and
  frame giving the sun's direction, attitude and moving cameras were not
  checked against the plan's list.
- **Speed.** Retained GPU frames, kept mesh trees, the disk caches and
  fast light landed. The frame-time table after the morning's two cuts
  was not re-run, and the plan's limit case (a dense 4K frame at 16
  samples) was not measured again.
- **The docs pass.** Done by one agent under review by the orchestrator,
  not the full three passes the docs method asks for; `cheeptune/README.md`
  still says `go build ./cmd/tune`, and `DEBT.md` still names `slayer
  smokes check`. Historical documents that name removed commands were
  left as records.
