# Shared work limits

The private work ledger models memory, CPU workers and GPU slots together. A render and a composite can declare their needs against the same value; a new immutable ledger is proposed only when all three resources fit. Duplicate IDs, invalid owners and malformed ledgers are refused. A proposed release requires the exact owner incarnation. The previous ledger is not changed by a proposal or release; neither operation proves that a process has stopped.

The value proposal combines the ledger with the existing host policy and latched stop transition; low disk produces a stopped proposal and unknown host conditions hold work. A bounded canonical record codec stores the host policy, latched stop and resource values with a checksum and predecessor digest. A pure transition proposal binds the predecessor digest and refuses changed policy or unknown host data. The checksum is integrity detection, not authentication or a durable transaction. This value calculation is not shared admission. It has no durable authority, process ownership, live grant, release protocol or connection to either engine. The existing composite command remains unavailable until those pieces and safe recovery exist. Tests for the ledger pass as of 2026-11-14.
