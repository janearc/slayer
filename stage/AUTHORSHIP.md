# Authored identity in a staged world

A staged surface may have come from a named YAML object. A renderer uses the
surface but does not need its authoring name; an editor needs that name to
select the same object and later find its source. Geometry or material alone
cannot identify it, because two authored imports can share both.

The world keeps an optional side table keyed by the stored surface pointer.
An author reference holds the collection and the authored name separately;
no slash-separated string parsing is needed for names that contain slashes.
The table is staging metadata and does not alter geometry or lighting. A
missing entry means unknown provenance, not permission to edit that surface.

The first supported sources are world boxes, spheres and imports. Every
surface of one import has the same authored reference; two instances retain
distinct references even when they share mesh data. The staging shift and
motion stay unchanged. Terrain, water, lights and volumes are not covered by
this slice and must remain unclaimed until their production paths supply
provenance.

Tests check distinct same-named collections, multi-part imports, shared meshes,
unchanged placements and an existing unannotated world surface. A shallow copy
of a world may share the side table only while it also retains the same surface
pointers. Any reconstruction that replaces pointers must explicitly transfer
or drop provenance; it must never guess a source from geometry.

The session also records all static surface parts made for each individually
named `scene.set.things` object, whether in space or on terrain. The name
identifies the whole authored placement, not each constructor-generated part.

Deforming surfaces are excluded until frame reconstruction can retain their
identity. The static parts generated by one stand share the stand's reference;
they do not invent an individual authoring path. Other generated groups
remain unassigned.
