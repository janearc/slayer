# Set editor prototype

Beauty and legibility are primary requirements. Use a restrained cool charcoal
workspace, warm mineral accents, generous space and a landscape that gives the
work a destination. The same application must be comfortable at a large text
scale. Prose colours must remain in the owner's contrast band, on each actual
surface; decorative edges and imagery do not substitute for readable text.

The next working step opens existing Slayer job and set YAML and draws a still
preview with the existing Slayer executable. The editor starts the configured Slayer itself,
never a second tracer, and the person's own render waits in no Game lane. Preview size is 640 by 360 with one ray per side, labelled
as a preview. Film jobs are refused for now, so opening one cannot accidentally
start a movie. Original files and their outputs remain untouched.

Each request snapshots the current draft to a new temporary file beside its
source, preserving all relative input paths. A job snapshot removes its output
destinations; the only output goes to a new preview directory. The temporary
input is removed when the process ends. Renderer output drives an indeterminate
activity indicator and a log, never invented percentages. Cancellation stops
the owned process group. Failed and stale results never replace a newer image.

Set documents use the existing ecosystem schemas where named. Legacy sets keep
syntax and duplicate-key validation, with domain validation left to Slayer.
Text size is adjustable; the colour presentation derives from Vaporwave Chroma.

The window has a project rail, an image workspace and a document inspector.
The set, camera/sequence and music areas have distinct places in the navigation.
Only set and job authoring are active in this pass. Planned areas are labelled;
they do not draw invented keyframes, audio waveforms or render progress.

The YAML document is the source of truth. Dropdowns change nodes in that same
document and retain its comments. Invalid edits remain visible and are never
replaced by an older valid draft. Controls refuse to mutate an invalid draft.

Validation uses Puzzlemouth's YAML front door and the pinned Slayer job schema.
Field guidance reads the descriptions in that same schema. It does not maintain
a parallel list of limits. The schema guide is metadata, never a config parser.
Open/save, body study selection, quality, renderer and image preset changes are
real prototype interactions. Schema-valid and renderer-ready are separate states.

Planetary studies are reference starting points. Selecting Venus or Titan selects
a draft set path and labelled mission reference image; it does not pretend that
terrain or atmosphere has been built. A user can also open an actual rendered PNG.

An immutable render request will eventually capture a document revision and
input hashes. Asynchronous render state belongs outside the widgets. The future
shot and music models will own their timing; widgets must not impose still-only
assumptions on the document or silently drop existing video/music job fields.

The public prototype CLI is Puzzlemouth. Screenshot export captures the Fyne
canvas; it does not draw a separate HTML imitation of the interface. Native and
software-canvas captures must be distinguished in their receipts.

Tests first cover comment-preserving edits, refusal without data loss, schema
diagnostics, future-field preservation and actual widget interactions. Visual
checks inspect layout at multiple window sizes and measure each prose palette
pair. Morning review, not an overnight agent review, is the next design gate.
